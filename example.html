Basic & single-field toasts

One field per toast, set through toastConfig.fields.

toastConfig.fields = [{ text: 'Saved successfully', className: 'toast-message toast-success' }];
toastConfig.custom = null;
showToast();

ArToast.show() with an untouched config renders the built-in default message. text goes through textContent, so the “Literal HTML” button prints its tags instead of rendering them.

Multi-field & vertical stacking

Each field becomes its own line with its own class: .toast-title, .toast-subtitle, .toast-timestamp.

toastConfig.fields = [
  { text: 'Order shipped', className: 'toast-title' },
  { text: 'Your parcel is on its way.', className: 'toast-subtitle' },
  { text: '09/29/2026 14:05', className: 'toast-timestamp' }
];

Empty description/timestamp inputs are dropped from the array before firing; the module would otherwise render empty lines.

Row grouping

Wrap fields in a nested array to put them side by side in a .toast-row.

toastConfig.fields = [
  { text: 'Wireless Headphones', className: 'toast-title' },
  [
    { text: 'Qty: 2', className: 'toast-qty' },
    { text: '$79.99', className: 'toast-price' }
  ]
];

The form shows the line total (unit price × quantity) in the price cell.

Custom content slot

toastConfig.custom takes a string or a DOM Node, appended after the fields in .toast-custom.

A · Plain string

toastConfig.custom = 'Free shipping applied to this order';

B · DOM Node, built fresh per call

const btn = document.createElement('button');
btn.addEventListener('click', () => { /* … */ });
toastConfig.custom = btn;   // a new node every time
showToast();

Edge cases

Reuse: the node moves out of the first toast into the second, leaving an empty .toast-custom behind. Skip the reset: custom is never cleared by the module, so the second toast inherits the first one's string. The other buttons on this site avoid both by resetting custom on every call.

Interactive toasts still auto-dismiss at 8000 ms. The module has no pause-on-hover or pause-on-focus.

    Eviction runs 1000 ms after the newest toast finishes its transform transition, so “On screen” can briefly exceed 5. Evicted and expired toasts share the same 1000 ms exit gap, so a batch created together also expires one second apart.

    If your CSS removes the transform transition, transitionend never fires and overflow eviction never runs. Lifetime expiry still works.

    Event log · observed from the DOM

      1. First toast → 2000 ms later #checkout gets .showC.
      2. Container bottom = 20 + drawer height + 10 px.
      3. Last toast expires → 5000 ms later .showC is removed and bottom returns to 20 px.

      Firing a toast inside that 5000 ms window cancels the close. Overflow evictions do not start the close timer; only normal expiries do.

      The drawer height is measured once, when it opens. The module does not re-shift the container if the drawer's content changes size afterwards.
